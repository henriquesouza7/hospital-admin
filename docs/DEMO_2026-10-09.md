## Preparação local segura

Para preparar um branch Neon novo e isolado, aplique todas as migrations
versionadas em ordem cronológica depois de criar o schema dos módulos. O ciclo
de consolidação inclui as cinco migrations de 08/10 listadas acima e as duas
migrations de 09/10: `20261009000000_bound_admission_export_snapshot.sql` e
`20261009010000_bound_purchase_and_production_exports.sql`. Elas instalam o
dashboard agregado e os snapshots das exportações. A migration adicional
`20261009020000_preserve_exact_financial_export_totals.sql` preserva os centavos
na exportação de gastos e cria `list_monthly_expense_totals_exact`. Ela é a
oitava migration do ciclo. Para preparar outro ambiente isolado, aplique as
cinco migrations de 08/10 e as três de 09/10 em ordem cronológica, depois de
preparar o schema-base, e confira as RPCs e permissões antes de apontar a
aplicação para ele. Nunca execute esse procedimento em `production`.

No Neon demo autorizado, a consulta read-only encontrou a RPC
`list_monthly_expense_totals_exact` presente, com retorno textual e permissões
esperadas. O banco não expõe ledger de migrations; portanto, essa evidência
confirma o objeto e suas permissões, mas não quando nem por qual mecanismo a
migration correspondente foi instalada. Não reaplique a migration quando a RPC
estiver presente. A confirmação do schema e das permissões não equivale à
homologação de login ou dos fluxos autenticados, que continuam pendentes.

1. No worktree isolado `hospital-admin-consolidacao-final`, use
   `pnpm install --frozen-lockfile`.
2. Configure `.env.local` somente nesse worktree, usando o branch Neon com ID
   `br-misty-recipe-b8muzwtd`, projeto `floral-breeze-18394345` e banco
   `neondb`. Os endpoints foram obtidos da configuração oficial Neon Auth e
   Data API desse branch; não copie variáveis do checkout antigo nem de
   production. Gere localmente `NEON_AUTH_COOKIE_SECRET` com pelo menos 32
   caracteres. Não grave nenhum valor de ambiente no Git ou neste documento.
3. Confirme a porta livre e defina `APP_BASE_URL` com a origem exata antes de
   iniciar `pnpm dev` quando não usar a porta 3000 (por exemplo,
   `http://localhost:3002`). A origem do callback deve ser a mesma que o
   navegador acessa. Neste branch, `allow_localhost=true` permite origens locais;
   em outro ambiente, confira `trusted_origins` e a configuração Auth. Sem
   `APP_BASE_URL`, a recuperação em desenvolvimento usa `http://localhost:3000`,
   mesmo que o servidor esteja em outra porta. O Neon Auth do branch permite
   localhost.
4. Entre pelo formulário oficial em `/login` usando a conta admin já existente.
   Não recrie a conta nem altere sua permissão. Não compartilhe senha, cookie ou
   token no chat.
