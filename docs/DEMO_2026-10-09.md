## Preparação local segura

Para preparar um branch Neon novo e isolado, aplique todas as migrations
versionadas em ordem cronológica depois de criar o schema dos módulos. As
migrations `20261008231000_aggregate_admission_dashboard.sql`,
`20261009000000_bound_admission_export_snapshot.sql` e
`20261009010000_bound_purchase_and_production_exports.sql` habilitam as
agregações do dashboard de Internações e as exportações por snapshot de
Internações, Compras e Produção. A migration
`20261009020000_preserve_exact_financial_export_totals.sql` preserva os centavos
na exportação de gastos e instala `list_monthly_expense_totals_exact`. Confira
no branch alvo as RPCs e permissões descritas acima antes de apontar a aplicação
para ele. Nunca execute esse procedimento em `production`.

No ambiente de demonstração autorizado, seis migrations anteriores foram
confirmadas como aplicadas; não as reaplique. A presença de
`20261008231000_aggregate_admission_dashboard.sql` ainda precisa ser verificada
pelo responsável do Neon. A migration
`20261009020000_preserve_exact_financial_export_totals.sql` está pendente e só
deve ser aplicada nesse branch demo após essa verificação. A confirmação de
schema e permissões não equivale à homologação de login ou dos fluxos
autenticados, que continuam pendentes.

1. No worktree isolado `hospital-admin-consolidacao-final`, use
   `pnpm install --frozen-lockfile`.
2. Configure `.env.local` somente nesse worktree, usando o branch Neon com ID
   `br-misty-recipe-b8muzwtd`, projeto `floral-breeze-18394345` e banco
   `neondb`. Os endpoints foram obtidos da configuração oficial Neon Auth e
   Data API desse branch; não copie variáveis do checkout antigo nem de
   production. Gere localmente `NEON_AUTH_COOKIE_SECRET` com pelo menos 32
   caracteres. Não grave nenhum valor de ambiente no Git ou neste documento.
3. Execute `pnpm dev`. Na validação atual, a porta 3000 já estava ocupada, então
   Next iniciou em `http://localhost:3001`; a porta usada deve ser confirmada
   antes da apresentação. O Neon Auth do branch permite localhost.
4. Entre pelo formulário oficial em `/login` usando a conta admin já existente.
   Não recrie a conta nem altere sua permissão. Não compartilhe senha, cookie ou
   token no chat.
